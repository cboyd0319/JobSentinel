# JobSentinel v3.0.0 Release Notes (Draft)

**Not released.** These notes describe the v3.0.0 core candidate for release review.
Full Stability, Performance and Security qualification, in that order, and
publication approval remain pending. No v3.0.0 download is offered by these notes.

The [v2.9.5 release record](v2.9.5.md) remains unchanged.

## Core Scope

This candidate follows the approved [105 Now / 82 Next boundary](../plans/v3/master-exec-plan.md).
Deferred enhancements, including shared-computer mode, portable distribution and
expanded native authentication, are outside v3.0.0.

- Opportunity Cases bring saved job, application, reminder and resume-fit evidence
  into local review. Daily mission offers bounded next actions without submitting
  applications or changing statuses silently.
- [Employer dossiers](../features/employer-intelligence.md) separate saved facts,
  source freshness and unknowns. Opening a dossier does not contact employers or
  turn local observations into hiring predictions.
- Regional search and pay guidance, reviewed first-run choices and a passive
  device check support broader job searches. Local model setup stays optional.
  Governed matching requires its reviewed model assets.
- [Recovery and data controls](../features/user-data-management.md) provide
  encrypted portable backups, staged restore, reviewed plaintext export and safe
  support reports. Pack installation remains subject to local review and trust checks.

Core workflows remain local-first. External AI is optional and disabled by default.
External notifications require user configuration. Final applications remain under
user control.

## Data And Update Boundaries

**Do not assume an in-place v2-to-v3 upgrade or a v3-to-v2 downgrade.** Startup
refuses pre-v3, unmarked and plaintext primary databases. Preserve the original
profile and backups without deleting data or relabeling files to bypass a refusal.
No v2 migration or backup-import path is qualified by this draft.

Supported v3 data is checked before migration or recovery. A Settings backup
contains settings, saved searches and cover letter templates, not the database.

Encrypted portable backups cover local records and exclude saved credentials.
Reviewed plaintext export is a separate disclosure workflow, not a restore format.
See [data coverage and recovery](../features/user-data-management.md) before changing installations.

Local update review requires installer-adjacent signed metadata, trusted publisher
identity, exact package integrity and compatible data readers. Production update
trust contains the approved public publisher key; installed update and rollback
qualification remains open. Development signing fixtures do not authorize installation
or prove native installer behavior.

## Qualification And Distribution Limits

- Windows 11+, macOS 26+ and Linux are target platforms. This draft does not claim
  completed native qualification, 8 GiB hardware proof or measured performance results.
- No-account macOS packages are not Developer ID signed or notarized. Unsigned
  Windows packages must be labeled accordingly. Do not infer platform trust from a checksum.
- Hosted and locally built artifacts require their respective evidence. Locally
  built macOS artifacts must not be described as GitHub-attested provenance.
- LinkedIn Workbench policy review is expired and remains blocked. Restricted-source
  policies cannot be overridden by local acknowledgement or saved credentials.
- Qualification signatures, notarization, Region artifacts and public-download
  verification remain release gates. No publication or public artifact pass is claimed.

The [Release Contract](../developer/RELEASING.md) owns the final phase and publication gates.
