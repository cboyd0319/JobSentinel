# JobSentinel v3.0.0 release notes

These notes describe the `v3.0.0` release. Use the
[latest GitHub release](https://github.com/cboyd0319/JobSentinel/releases/latest)
for current downloads.

## Overview

JobSentinel 3.0.0 is a major release. It gives each job one local place to
review, prepare, and track it. It adds encrypted backups, offline recovery, and
stricter rules for job sites. Your data stays on your computer. Outside AI
stays optional and off by default. You still review every outside action and
submit every application yourself.

Version 3.0.0 is the first supported starting point for future updates.
Releases before it aren't supported as an upgrade source.

Shared-computer mode, portable distribution, and expanded native sign-in are
planned enhancements and aren't part of 3.0.0.

## If you used version 2

- Version 3.0.0 can't open, upgrade, or restore data, settings, or backups from
  version 2.9.5 or earlier. There's no supported upgrade path.
- To start fresh, close JobSentinel and rename your version 2 folders. Don't
  delete the folders or JobSentinel's saved keys. Follow
  [Coming From Version 2](https://github.com/cboyd0319/JobSentinel/blob/v3.0.0/docs/user/UPDATES.md#coming-from-version-2).
- If 3.0.0 finds version 2 data, it opens a recovery screen instead of the app.
  It doesn't change or remove that data.
- In 3.0.0, add your searches and settings again. Enter saved passwords and
  connection links again in **Settings**. Old saved passwords aren't imported.
- Going back from 3.0.0 data to version 2 isn't supported. The same guide
  shows how to use 2.9.5 again with your renamed version 2 folders.

## What's new for job seekers

- **Opportunity case:** **Open case** on the dashboard shows a job's source,
  freshness, application, interview, offer, and resume evidence in one view.
  It suggests Apply, Maybe, Skip, or Research more, with plain "Why not this
  job?" reasons.
- **Daily mission:** **Applications** starts with three to seven concrete next
  actions. Picking one never changes an application status on its own.
- **Prepare this job and debriefs:** Get a local checklist before you apply.
  After an interview, save what was asked and what comes next.
- **Resume evidence:** Matches point to the resume evidence behind them.
  Missing or outdated evidence stays visible instead of turning into a claim.
- **Military transition:** Turn confirmed service, credentials, and clearances
  into reviewed civilian wording. Veteran status and other protected answers
  stay with you to answer by hand.
- **Employer dossier:** See what's known about an employer, with sources and
  dates. It's an evidence view, not a rating or fraud verdict.
- **Backups and leaving:** Make an encrypted backup of jobs, applications,
  resumes, notes, reminders, and history. A restore is checked first and
  applied when the app restarts. Export a readable copy when you want to leave.
  Backups don't include saved passwords, and a readable export can't be
  restored. A Settings backup holds settings, saved searches, and cover letter
  templates, not your job records.
- **Recovery:** If the app can't start, a local recovery screen works without
  internet. **Privacy Doctor** checks local privacy settings without reading
  secrets.
- **Drag and drop:** Drop a resume, job posting, or encrypted backup on the
  window. Nothing is saved until you choose what to do with it.
- **Browser Import:** Each copied import button works once, for the one website
  you confirmed, and expires after about ten minutes.
- **Local Match Check:** **Settings** shows whether local matching models are
  healthy. Matching still works without a model download.

## Job site changes

- Scheduled checks for Built In, Dice, SimplyHired, Glassdoor, and JobsWithGPT
  are off after a policy review. Your saved settings stay, but they can't send
  requests.
- Y Combinator jobs open only as links you choose to open.
- Sign-in sites such as LinkedIn need your exact acknowledgement first.
  JobSentinel still stores no sign-in details from those sites.
- LinkedIn Workbench stays blocked because its policy review expired. An
  acknowledgement or saved sign-in can't override a site policy.

## Technical notes

- Databases need v3 compatibility records. Pre-v3, unmarked, and newer
  unsupported data stops at recovery. The app won't create a database key while
  existing data, backups, restore files, or update snapshots are present.
- Saved credentials use only the encrypted vault. Settings files with retired
  plaintext credential fields are refused and left unchanged.
- Windows keeps database and vault keys in Credential Manager with device-local
  persistence. A missing key fails closed.
- When existing data can't be unlocked, only a recovery restore can create a
  new key. The recovery screen warns that earlier data may become unreadable.
- Signed packs install through quarantine and review. Executable packs are
  limited to reviewed typed actions. One approved Region publisher can sign
  static, local-only Region packs.
- Local updates need signed metadata next to the installer, a trusted
  publisher, an exact package match, and compatible data readers. Version 3.0.0
  trusts one approved update publisher key.
- Release builds create a draft first. Publication checks recorded Stability,
  Performance, and Security phase evidence against the exact draft package
  checksums.
- Tauri and other dependencies received security patch updates.

## Platform notes

- Windows installers aren't code signed and include `_unsigned` in their
  names. The macOS package status is described below.
- A locally built macOS package has no GitHub build attestation. Its checksum
  and software bill of materials are still verified.
- A checksum shows the download is intact. It doesn't show that the package is
  signed or trusted by your operating system.
- Every package has a matching `.sha256` checksum file. Verify it before you
  install.

## Updating

JobSentinel doesn't update itself silently. Verify the downloaded package
checksum, and follow
[Updating Or Going Back](https://github.com/cboyd0319/JobSentinel/blob/v3.0.0/docs/user/UPDATES.md).
Version 2 Settings backups aren't supported in 3.0.0.
